The event

Built at GDG Hacks 2026, a 24-hour hackathon at the University of Guelph in May 2026 with about 130 students from across Ontario, as a team of four.

How it works

When a pull request is opened or updated, GitHub sends a signed webhook to a Go server. The server verifies the signature, uses AST-aware chunking to pull out only the functions the PR changed, and sends each one to Claude for a security review. Findings are posted back as inline PR comments and GitHub Check Run annotations on the exact line, and shown in a live Next.js dashboard with severity, CWE, file and line.

  1. 1PR openedor updated
  2. 2Webhooksigned by GitHub
  3. 3Go serververify + AST chunking
  4. 4Claude reviewone call per function
  5. 5 PR comments+ Check Run annotations Dashboardlive, in Next.js

My role

  • Tuned the Claude review pipeline in Go: deterministic output (temperature 0), prompt caching, XML-structured inputs, a calibrated 4-level confidence scale and a few-shot example.
  • Added retry with exponential backoff on rate limits, plus validation that deduplicates findings and drops incomplete ones.
  • Deployed the Go server to Fly.io: wrote the Dockerfile and set up secure private-key loading.
  • Built UI improvements to the Next.js dashboard, including a resizable sidebar.

How it works

You enter the thickness and quantity of each part and washer, flat and bevel, and pick a bolt diameter from 1/2″ to 1″. The app adds a nut-and-thread allowance based on the diameter and rounds the total up to the next 1/4″.

The last 7 results are saved in the browser with localStorage, and you can delete a result and undo the delete. Every push to main builds and deploys the app to GitHub Pages through a GitHub Actions workflow.
